## 3. ⚠️ 不能写的主张(会被追问穿)

| 说法 | 为什么不能写 |
|---|---|
| ❌ "用 import-linter / 分层检查工具保证单向依赖" | `pyproject.toml` **没有** import 方向检查工具。该约束是**文档约定 + 评审**,非自动化。只能写"靠约定约束" |
| ❌ "搭建 CI/CD 流水线 / GitHub Actions" | 仓库**无 CI 配置**,验收均为本地脚本 |
| ❌ "线上 QPS / 延迟 / 可用性 99.x%" | 这是单机内部工具,**没有**生产流量指标。写了必被追问数据来源 |
| ❌ "带领 N 人团队" | 无团队规模事实 |
| ❌ "支持高并发" | 浏览器池 `max_contexts=4`,是**低并发**设计。要写就写"受控并发" |

## 4. 可展开的面试细节(被追问时的纵深)

| 追问方向 | 可展开的点 |
|---|---|
| 为什么域要隔离? | 三个域的变更节奏与失效模式不同;跨域直接 import 会让"改比价"波及"推送"。注入点收敛到 `runtime.py` 一个文件,便于审阅影响面 |
| `no_data ≠ failed` 的业务含义? | 酒店当天停业就没有数据,这不是程序错误。若两者混同,日报会把"正常停业"报成故障,导致告警疲劳 |
| 为什么引异常分类而不是布尔重试? | 骨架页未就绪该重试;被风控拦下重试只会加重风控;需人工过验证码则必须停下来等人。三类处置方式完全不同 |
| 双通道为什么要合并而不是二选一? | 接口给 ID + 精确坐标(距离可信),DOM 给价格。各自最强处不同,所以合成一条记录,而不是取其一 |
| 幂等怎么做的? | 唯一约束落在(酒店, 平台, 日期, 时刻)上;同日多次采集各留一份,重跑靠 upsert 不新增行。踩过 NULL 在 PG 唯一约束里互不相等的坑,用 `NULLS NOT DISTINCT` 修 |
| 怎么保证平台改版后能快速定位? | 把"取不到价"拆成可观测的中间态:接口命中数、选择器逐条命中数、页面价格节点 class 链。诊断脚本化,不靠人肉翻日志 |
