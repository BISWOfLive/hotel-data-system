# 简历:Java 后端岗位 · 本项目怎么用

> 背景:本项目是 **Python** 实现,求职方向是 **Java 后端**。
> 这份文档解决两件事:
>
> 1. **怎么把它写到 Java 后端简历上而不显得"投错岗"**;
> 2. **面试官追问 Python 细节时,怎么把话题接到 Java 生态的对应物上**。
>
> 核心判断:**系统设计、并发模型、可靠性设计、数据建模是语言无关的**;
> 而语言与框架细节是语言相关的。所以策略是 —— **主动说明差异,把火力引到前者**。

---

## 一、口径:怎么定性才站得住

### ✅ 推荐口径

> 「后端系统设计与实现(用 Python 落地)」

在项目行里**主动标注语言**,不要藏:

```
酒店经营数据自动化系统 | 个人项目 | Python 实现(系统设计思路与 Java 后端通用)
```

**为什么主动标注反而是加分**:面试官看到"Python 实现"会先有疑虑;
你紧接着能讲清楚"为什么选 Python(生态里 Playwright/异步 I/O 更顺手)、
如果换 Java 我会怎么选型(Netty / 虚拟线程 / Spring 定时任务)",
疑虑就转成了**技术判断力**的证据。

### ❌ 不要这样

| 写法 | 问题 |
|---|---|
| 只写技术栈不写语言 | 面试官默认当 Java 问,一问就穿 |
| 硬说成 Java 项目 | 造假,风险极高 |
| 完全不提这个项目 | 白丢一个 4 万行、有完整工程闭环的作品 |

## 二、简历文案(Java 后端版)

### 项目条目

> **酒店经营数据自动化系统** | 个人项目 | Python 实现 · 系统设计与 Java 后端通用
> FastAPI / PostgreSQL / 异步 I/O / 定时调度 · 41,910 行 · 21 张表 · [GitHub](https://github.com/BISWOfLive/hotel-data-system)

**① 分层架构与模块边界**
按"业务域 / 基础设施 / 装配"三层组织三个业务域(数据采集、消息推送、价格比价),
**域间禁止互相依赖**,依赖注入统一收敛到装配层。
用**统一状态机**(`ok / degraded / no_data / failed`)在**类型层面**区分"无数据"与"失败",
避免把业务正常态(当天无数据)上报成系统故障。

**② 单线程异步 I/O 与长连接服务**
把旧方案的"同步 socket + 一线程一连接"重构为**事件循环 + 协程**模型:
单进程支撑多路长连接,支持心跳保活、大文件分片传输,
并按协议语义区分**需要 ack 与不需要 ack** 的两类消息(前者防丢文件,后者防超时重发导致重复)。

**③ 可靠性:异常分级重试 + 全链路幂等**
为外部依赖链路设计**三级异常分类**(可重试 / 不可重试 / 需人工介入),
使"依赖未就绪"可自动重试、"被限流"不加重压力、"需人工"正确停止。
**30 处**基于唯一约束的 upsert 实现幂等;**任务采用"抢占即执行"**防并发重跑,
并支持服务停机后按时间窗补跑。

**④ 受控并发与资源池化**
实现**会话资源池**,按业务三元组复用连接上下文;
超出上限时 **LRU 淘汰空闲资源**,全部占用时排队等待,
把并发压在上限内以避免资源耗尽。

**⑤ 测试与验收工程化**
编写 **84 项编号验收 + 167 条断言**,覆盖数据层、接口契约、安全默认值与降级行为,
每项输出可核验证据而非仅"通过/失败";配套诊断脚本,
外部依赖变更时可逐项定位失效点。

### 摘要

> Java 后端方向,具备完整的后端系统设计与落地经验:
> 分层架构、异步 I/O、关系型数据建模、幂等与重试设计、资源池化、测试工程化。
> 独立完成一套 41,910 行、21 张表的系统(用 Python 落地,设计与 Java 后端通用)。

## 三、把项目亮点翻译成 Java 语言(面试话术)

被问"这部分在 Java 里你会怎么做"时,按这张表回答:

| 项目里的做法 | Java 对应方案 | 说明话术 |
|---|---|---|
| 事件循环 + 协程做长连接 | **Netty** 的 EventLoop;或 JDK 21 **虚拟线程** | 「本质都是把 I/O 等待从线程上摘下来,单线程管多连接。Java 里我会用 Netty 的 ChannelPipeline,或者虚拟线程 + 阻塞式写法换可读性」 |
| 浏览器/会话资源池 + LRU | **HikariCP** 连接池 / 对象池 | 「和你熟悉的连接池是一回事:上限保护 + 空闲淘汰 + 等待队列」 |
| `ON CONFLICT DO NOTHING` 抢任务 | 唯一约束 + `INSERT ... ON CONFLICT`;或 Redis `SETNX` | 「思路是让数据库当仲裁者,抢不到就是已跑过。分布式场景我会换成 Redis 锁或 Quartz 的集群模式」 |
| 状态机 `ok/degraded/no_data/failed` | 枚举 + 状态流转校验 | 「关键是把'业务空态'和'系统故障'分开建模,不然后面告警会误报」 |
| 异常三级分类 | 自定义异常体系 + 重试策略 | 「我会定义 `RetryableException` / `FatalException`,配合 Spring Retry 的退避策略」 |
| 7 个增量迁移 | **Flyway** / Liquibase | 「版本化迁移,数据库变更进代码评审」 |
| 22 个定时任务集中注册 | Spring `@Scheduled` / Quartz | 「任务定义集中一处,配置只放开关不放时刻」 |

## 四、⚠️ 高风险追问与应对

### Q1:「你为什么用 Python 做后端?是不是不会 Java?」

**不要辩解,直接给对比**:

> 「这个项目选 Python 是因为它的异步生态和浏览器自动化库更顺手,不是能力边界。
> 我在这个项目里练的是后端通用能力:分层、并发模型、幂等、数据建模、测试工程化。
> 语言层面我熟悉 Java 的……(讲你的真实 Java 能力)」

⚠️ **诚实边界**:如果你 Java 只到"会用 Spring Boot 写 CRUD",
不要吹 JVM 调优、并发包源码。面试官一定会问。

### Q2:「你这个并发怎么做的?有并发问题吗?」

这个项目的真相是:**单进程 + 受控低并发**(资源池上限 4)。
**不要吹高并发**,坦白说:

> 「这个场景是受控并发,我把上限压住避免资源耗尽 —— 做的不是高吞吐,是**不出错**。
> 高并发场景我会关注……(讲你会的:线程池参数、锁粒度、无锁结构)」

### Q3:「你了解 JVM 吗?」

这是个**陷阱题**。项目全程 Python,**答不上来很正常** ——
但别硬答。正确做法是提前补 JVM 基础(内存分区、GC 类型、类加载),
因为这是 Java 后端**必考**,和项目无关。

### Q4:「4 万行是你一个人写的?」

按你的真实情况回答。如果部分由团队完成,说清边界;
面试官反感的是冒领,不是协作。

## 五、给你的补强清单(优先级从高到低)

| 优先级 | 补什么 | 为什么 |
|---|---|---|
| 🔴 **最高** | **Java 主项目** —— 用 Spring Boot 做一个能讲的系统 | Python 项目只能当**加分项**;Java 岗的**主线**必须是 Java 项目,否则简历会被判"不匹配"筛掉 |
| 🔴 高 | **JVM 基础 + 并发基础** | Java 后端必考,与项目无关,必须单独准备 |
| 🟡 中 | 本项目的**性能实测数字** | 单次任务耗时、批量耗时 —— 有数字才能讲"优化" |
| 🟡 中 | 讲清**个人边界** | 哪些模块你独立完成 |
| 🟢 低 | 把本项目亮点**用 Java 重写一遍** | 若能做一个 Java 版最小实现(哪怕只做资源池 + 幂等),说服力翻倍 |

> **最重要的一条**:这个项目在 Java 岗简历上应该占 **1 条**,而不是全部。
> 它的作用是证明"**我懂后端系统怎么做**",不是证明"我会 Java"。
