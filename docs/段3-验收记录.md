## 4. 施工中发现并修掉的**计划书之外**的问题

### 🔴 4.0 取价链路的 6 个 bug(真机联调阶段查出,**4 个属"看起来正常但数据是错的"**)

> 这一段值得单独记:它们**不是**"取不到数据"这类显式失败,
> 而是**静默错误** —— 报告生成成功、格式完好、数字像模像样,
> 但内容是错的。这比"报错"危险得多。

| # | Bug | 后果 | 为什么容易被漏掉 |
|---|---|---|---|
| 1 | **`wait_for` 拒绝 async 条件** | 所有 DOM 等待失效;后续在已关闭页面上炸 `TargetClosedError` | 修"同步 lambda 返回协程"时**过度收紧**,把正确写法也拒了。从 `await` 角度两者不可分 —— 必须靠"嵌套协程"来区分 |
| 2 | **`http_text` 调了不存在的 `http.get()`** | 城市 sitemap 永远失败 | 只在**未登记 `ebk_hotel_id`** 的酒店上走;4 家生产酒店都登记了 id |
| 3 | **`self._build_list_url`** 调了不存在的属性 | 同上 | 同一条兜底路径 |
| 4 | **登录检测用 cookie 数量** | **匿名访问被判成"已登录"**,登录态写盘并标 `valid`;而页面仍显示「登录看低价」 | 携程前台匿名也种 76 个 cookie。判的是"浏览器来过这个站",不是"这个人登录了" |
| 5 | **接口条目与 DOM 卡片没合并** | 同一家店在报告里**出现两次**(一条有坐标、一条有价) | 需要接口与 DOM **同时**返回数据才暴露 |
| 6 | **评分正则不支持千分位** | `4.4 1,070 点评 xxx` 整段被当酒店名 → 合并失败(表现为 bug 5) | 千分位只在点评数 ≥1000 时出现 |

**修法**:每条都配了对照实验脚本(`docs/../scripts/diag_*.py`),并且
`wait_for` 现在会**主动喊出错误写法**;登录检测改成以**页面信号**为准
(「登录看低价」按钮),不再猜 cookie 名。

### 🔴 4.0.1 平台真实行为与计划书不符(3 处,均有对照实验)

| 计划书 | 实测 | 证据 |
|---|---|---|
| §5.6「接口命中则**零点击**取价」 | **携程接口结构性不带价** —— 4 锚点 × 20 家 = **80 家全部 `priceStr="?"`**;而详情页 DOM 卡片有价 | `scripts/diag_ctrip_price_by_hotel.py` |
| 美团 `list.html` 直达 | 该端点**已 404**(CDN `NoSuchKey`) | `scripts/diag_meituan_url.py` |
| 美团城市解析 | 城市名必须解析成 `cityId`;否则**硬编码成都(59)会取回成都的酒店** | 实测:莱州→529、都江堰→576、蒙自→红河州 338 |

### 🔴 4.1 `cmp_price_key` 唯一约束**形同虚设**(实测发现,迁移 `0006` 修复)

`0005` 建的唯一约束含 `room_type`,而段3 只取列表页起价、`room_type` **恒为 `NULL`**
—— 而 **PostgreSQL 的 UNIQUE 里 `NULL` 互不相等**,于是:

* `INSERT ... ON CONFLICT ... DO UPDATE` **照常工作**(ON CONFLICT 用约束仲裁);
* 但**裸 INSERT 不被拒绝** —— 实测同一行连插两次**两次都成功**。

这正是 **D8 的同类病**:schema 里明明写着 UNIQUE,实际不挡重复,而且**更难发现**
(旧系统是"没有约束",这里是"有约束但不生效")。

**修法**:迁移 `0006` 改为 `UNIQUE NULLS NOT DISTINCT`(PG 15+,本机 16.15)。
修复后实测:第二次裸插 **`IntegrityError`**。

### 🟡 4.2 `upsert_target` 会把「已停用」悄悄改回启用

`enabled` 原默认 `True` → 每次 `targets add` / `import` / `set` 都会**重新启用
管理员手动停用的目标** —— 而"停用"通常正是因为那家店在改版/风控期间不想跑。

**修法**:`enabled` 默认改为 `None` = **不改动已有行的启用状态**。

### 🟡 4.3 旧清单「两个文件都列了同一家店」被去重丢掉一个 mode

实测 `price_targets.txt` 只有 1 家店,而它**同时也在** `compare_hotels.txt` 里。
按"同名去重只留先到的"处理 → 它只剩 `mode='batch'` →
**`compare.collect`(定时采集)一个目标都没有** → 09:00 日报的比价段在**数据层**就断了。

**修法**:合并为 `mode='both'`,两个任务都选得到;`list_targets` 查询
**同时匹配 `both`**。

### 🟢 4.4 `deep_find_coords` 的调用作用域

旧 `geo.deep_find_coords` 返回**扁平列表**,无法与酒店逐条对齐(旧系统"抓到坐标却接不上线"
的技术原因)。段3 改为**逐条对象**提取(`coords_from_obj`),并新增测试断言
"两条记录各自取到自己的坐标、不串台"。

### 🟢 4.5 `zhipuai` SDK 实测 **import 就失败**(缺 `sniffio`)

计划书 §3 写「视觉兜底 → `zhipuai`(段1 已引入)」。实测该包**装了但坏**。
段3 改为**直接走 HTTP**(智谱 OpenAI 兼容端点),复用已有的 `httpx`
—— 于是 `VISION_ENABLED=0` 时**零依赖、零网络**是**结构性保证**,
而不是靠 `if` 判断,且少一条 SDK 升级风险。
