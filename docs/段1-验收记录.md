## 3. 验收过程中发现并修复的缺陷

验收不是走过场 —— 下面每一条都是**跑出来的真 bug**,不是自查出来的"风格问题"。

| # | 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|---|
| **1** | **`get_api_rules()` 必然抛错** | 任何需要规则的命令全挂 | `_RulesRoot` 把 `_comment` / `_screenshot_comment` 写成**下划线字段名**;pydantic v2 把下划线名当**私有属性**,于是 `extra="forbid"` 拒绝 JSON 里真实存在的注释键 —— **一个纯注释键能把整个规则加载炸掉** | 改成普通字段名 + `alias="_comment"`;`push_rotation.json` 的 `_comment` 同修 |
| **2** | **交叉校验误报 6 处** | 修完 #1 后仍加载失败 | `apis[].match` 有**两种写法**:定义名 **或 URL 片段**(实测 97 条里有多条是后者);且 3 条 `apis[].fields` 为空是**合法的** | `match_resolves()` 同时按名字(双向包含)与 URL 片段匹配;空 `fields` 降级为 warning |
| **3** | **`fixed_daily` 返回的是页名** | `rotation --date` 打印出"每日固定采 7 项:(经营报告, 竞争圈动态, …)" | `all_sub_modules()` 返回 `(page, sub)` 二元组,直接解包拿到的是**页名** | 改为 `sub.name for _page, sub in …` |
| **4** | **限频自检把正常限频判成违例** | V16 报 17 次违例,但最小间隔明明是 0.6003s | 用"进临界区时距上次放行的差"当间隔 —— 那个值天然小于阈值(那正是"需要补睡"的原因) | 间隔改为在 **sleep 之后**用 `release - 上次 release` 量 |
| **5** | **`coalesce` 保不住旧值** | V10 空值重跑后 `module_screenshots_json` 变 `null` | SQLAlchemy 的 JSON/JSONB 类型默认 `none_as_null=False`,把 Python `None` 编成 **JSON 字面量 `null`** 而不是 SQL NULL,于是 `coalesce('null'::jsonb, col)` 返回 `'null'::jsonb` | 值为 None 时**自赋值列本身**(与 COALESCE 的"保留旧值"等价,且不引入 JSON null) |
| **6** | **ORM 身份映射导致 `find_report` 读到旧对象** | 同一 session 内"读→写→读"拿到写前的值 | 写入走 Core `update()`,不刷新 ORM 身份映射 | `find_report` 加 `populate_existing=True` |
| **7** | **`alembic.ini` 在中文 Windows 上读不了** | `UnicodeDecodeError: 'gbk' codec can't decode` | Alembic 用 `encoding="locale"` 读 ini;文件里的中文注释在 GBK 环境下炸 | `alembic.ini` 改为**纯 ASCII**,中文说明移入 `env.py`(UTF-8) |
| **8** | **CLI / 脚本在 GBK 控制台必崩** | `UnicodeEncodeError: 'gbk' codec can't encode character '✓'` | Windows 控制台默认 cp936;`✓`/`✗`/`·` 编不出来 —— 而且往往是"**活干完了、打印结果时炸**",看起来像业务失败 | `hoteldata.logging.configure_stdio()` 统一把 stdout/stderr 切 UTF-8;CLI 入口与 `scripts/*` 都调 |

### 5.1 抢救:不用重新登录就找回会话

定位到 #14 时,用户的 `login` 进程**仍在运行**。而 `_commit_state()` 的顺序是
「写文件 → 探活 → 回滚」,所以**有效登录态仍会短暂写在文件里**(约 250ms)。

`scripts/rescue_state.py` 以 **12ms** 高频轮询该文件,把不属于基线的那一版抓了下来:

```
基线指纹 95ec2e41a375  大小 65299B  cookies 14
抓到一个候选: 16059B  cookies=19  鉴权=['imislogin','randomkey','usersign','usertoken']
```

→ 再用**修好的**探活验证 → `探活通过(fetchVisitorTitleV2 → HTTP 200)`。
**用户的会话完整找回,不必重新登录。**

> 这个抢救脚本的通用价值:凡是"写了又被回滚"的状态文件,都可以这样捞。
> 它**不是**绕过验证 —— 抓到的候选照样要过探活才转正,过不了就留在
> `.rescued` 里供排查。
