# 推送前必读:**这个仓库不能带什么**

> 起因:旧系统在这里栽过(D2/D3)—— ``.gitignore`` 漏了两条路径,
> 结果**4 个真实酒店账号会话 Cookie** 与 **1,936 个含凭据的浏览器配置文件**
> 被 git 跟踪。新项目把红线写死在 ``.gitignore`` 里,并且**加了自动化检查**。

## 一、红线:永远不进仓库

| 路径 / 形态 | 为什么不进 |
|---|---|
| ``.env`` | 含 ``DB_URL``(库口令)、``ZHIPU_API_KEY``、``ADMIN_PASSWORD_HASH``、``MANAGE_CHATIDS`` / ``OPS_CHATID`` |
| ``config/secret.key`` | Fernet 主密钥(登录态加密用) |
| ``var/states/**`` | **登录态 Cookie**(`<platform>__<role>__<alias>.json`)—— 最敏感的一类 |
| ``var/**`` | 运行产物:原始响应、报告、截图、DB dump |
| ``storage_states/`` / ``storage_state*.json`` | 旧布局的登录态 |
| ``.edge-profile/`` / ``.chrome-profile/`` | 浏览器用户目录(**含凭据**) |
| ``logs/`` / ``*.log`` | 可能含 URL 与 Cookie 片段 |
| ``*.db`` / ``pgdata/`` | 数据库文件 |
| ``legacy/*`` | 旧代码冻结区 |

**新增敏感路径时,必须同时更新** ``.gitignore`` 与本文档。

## 二、容易被忽略的:**捕获来的真实标识**

``.gitignore`` 挡的是**路径**,挡不住"真实值被写进规格文件/文档/注释"。
本项目实测就出现过,而且**分布在四个地方**:

| 真值 | 原本出现在 |
|---|---|
| ``clientId`` / ``_fxpcqlniredt``(20 位数字) | ``config/api_rules.json``(35 处)、``portal.py``(源码硬编码默认值)、归档规格 md |
| 设备指纹 ``fp`` | 同上 |
| 访客 ``vid`` | 同上 |
| ``rmsToken``(含**真实出口 IP**) | ``config/api_rules.json``(35 处) |
| 真实企微 ``chatid`` + 真实 userid | 归档 ``aibot_targets.json``、迁移 docstring、基线报告 |
| ``x-traceID`` 前缀 | 归档诊断 dump |

### 处理方式

```bash
# 1) 先看清单(不写文件)
.venv\Scripts\python.exe scripts\sanitize_captured_ids.py --dry-run --include-docs --include-md
# 2) 执行
.venv\Scripts\python.exe scripts\sanitize_captured_ids.py --include-docs --include-md
```

**保形替换**:值换成等长占位符(``00000A-00000B-00000C`` 等),
所以文件仍是"该带哪些头/字段"的**规格**,但对不上任何真实会话。脚本幂等,可反复跑。

### ⚠️ 一个必须知道的坑

``src/hoteldata/domains/collect/api.py`` 的::

    TRACE_PREFIX = "09031123114691476238-"

是**平台协议要求的 ``x-traceID`` 前缀字面量**(``gen_trace()`` 用它拼 trace)。
它长得和捕获的 ``clientId`` 很像,但**必须原样保留** —— 换成占位符会让平台拒请求。
所以脱敏脚本里有一个 ``PROTECTED`` 列表把它排除掉,**不要**为了让扫描器变绿而"顺手"改它。

> 这条坑真实发生过:最初想用 ``0903\d{16}`` 整仓替换,那会把 trace 前缀
> 和 clientId **一起**抹掉 —— 而这两者命运相反。

## 三、推送前跑这个

```bash
.venv\Scripts\python.exe scripts\check_secrets_before_push.py
```

它按**内容特征**(不是路径)扫全仓:

* 🔴 **阻断项**:明确凭据字面量(口令赋值、连接串含口令、私钥块、webhook key …);
* 🟡 **需复核项**:像标识符的东西(chatid、长 hex、手机号、邮箱);
* 🟢 **红线路径的忽略状态**(``git check-ignore``)。

**有 🔴 就先别 push。** 若确认是误报(例如把口令**打码后**再拼 DSN 的代码),
在两处都标注:

```python
return f"postgresql://{user}:***@{host}:{port}/{db}"  # secretscan:ignore
```

扫描器会跳过带该标记的**行**(所以要标在命中那一行)。

## 四、如果真泄漏了

1. **先转密钥**:改库口令、重新生成 ``config/secret.key``、换企微 webhook key;
2. 再清历史:``git filter-repo --path <文件> --invert-paths``(或 BFG);
3. **重新登录全部平台账号** —— 会话 Cookie 泄漏等同于账号被借用;
4. 最后才强推,并通知所有协作者重新 clone(旧克隆里仍有历史)。

> 顺序很重要:**转密钥要在清历史之前**。清历史只是让"以后看不到",
> 已经 push 出去的内容在别人机器上可能已经被拉走。
