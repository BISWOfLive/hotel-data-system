### 1.3 窗口名规范化 `normalize_window`

`api:117-137` 逐字抄录（判定顺序 = 优先级）：

```python
def normalize_window(window: str) -> str:
    """窗口名规范化：窗口名 → 中文窗口名；未知抛 ValueError。"""
    if not isinstance(window, str) or not window.strip():
        raise ValueError(f"窗口参数非法: {window!r}")
    w = window.strip()
    if is_valid_window(w):  # 规则层单一事实源：中文七窗 + 未来30天/next_30d
        return WINDOW_NAMES.get(w, w)
    if w in WINDOW_NAMES:   # 内部键别名扩展：yesterday/last_7d/...（next_30d 已在上支处理）
        return WINDOW_NAMES[w]
    if w in WINDOW_KEYS:    # 理论上已被 is_valid_window 覆盖，防御保留
        return w
    raise ValueError(
        f"未知数据窗口: {window!r}（可选: {'/'.join(WINDOW_CHOICES)}；"
        f"内部键别名: {', '.join(sorted(set(WINDOW_NAMES) - {'next_30d'}))}）"
    )
```

精确语义（复现要点）：

1. 非 `str` 或 `strip()` 后为空 → `ValueError(f"窗口参数非法: {window!r}")`（`api:125-126`）。
2. 先做 `strip()`；后续所有比较都用 `w`。
3. 命中 `WINDOW_CHOICES`（11 名之一）→ 返回其**中文名**（`WINDOW_NAMES.get(w, w)`；`next_14d`/`next_30d` 不在 `WINDOW_NAMES` 的键里，原样返回）。
4. 否则若 `w` 是内部键（`yesterday`/`last_7d`/`last_week`/`last_30d`/`last_month`/`today_realtime`/`realtime`）→ 返回对应中文名（`api:130-131`）。
5. 否则抛 `ValueError`，消息中「可选」部分由 `'/'.join(WINDOW_CHOICES)` 动态拼出，「内部键别名」部分为 `sorted(set(WINDOW_NAMES) - {'next_30d'})`（`api:134-137`）。
6. **返回值恒为中文名**（除 `next_14d`/`next_30d` 两个内部键原样返回）。

### 1.4 「窗口 → 日期区间」精确算法 `compute_window_range`

`api:140-173` 逐字抄录（**闭区间 `[start, end]`，两端都含**）：

```python
def compute_window_range(window: str, today: Optional[date] = None) -> tuple[date, date]:
    t = today or date.today()
    key = WINDOW_KEYS.get(normalize_window(window))
    if key == "yesterday":
        return t - timedelta(days=1), t - timedelta(days=1)
    if key in ("today_realtime", "realtime"):
        return t, t
    if key == "last_7d":
        return t - timedelta(days=7), t - timedelta(days=1)
    if key == "last_week":
        monday = t - timedelta(days=t.weekday())          # 本周一
        return monday - timedelta(days=7), monday - timedelta(days=1)
    if key == "last_30d":
        return t - timedelta(days=30), t - timedelta(days=1)
    if key == "next_14d":
        return t, t + timedelta(days=13)
    if key == "next_30d":
        return t, t + timedelta(days=29)
    # last_month:上一自然月
    first_this = t.replace(day=1)
    last_prev = first_this - timedelta(days=1)
    return last_prev.replace(day=1), last_prev
```

**逐窗口口径表**（`t` = 基准日；`today` 缺省 = `date.today()`，`api:153`）：

| # | 中文名 | 内部键 | `start` | `end` | 天数 | 基准 | 备注 |
|---|---|---|---|---|---|---|---|
| 1 | `昨日` | `yesterday` | `t - 1d` | `t - 1d` | 1 | **昨日** | 单日窗口，`start == end` |
| 2 | `今日实时` | `today_realtime` | `t` | `t` | 1 | **今日** | 与 `实时` 同区间、不同键 |
| 3 | `过去7天` | `last_7d` | `t - 7d` | `t - 1d` | 7 | **昨日** | = 昨日−6 ~ 昨日，两端含 |
| 4 | `上周` | `last_week` | 上周一 | 上周日 | 7 | **今日**（非昨日） | 上一自然周（周一~周日），两端含 |
| 5 | `过去30天` | `last_30d` | `t - 30d` | `t - 1d` | 30 | **昨日** | = 昨日−29 ~ 昨日，两端含 |
| 6 | `上月` | `last_month` | 上月1日 | 上月最后一日 | 28~31 | **今日**（非昨日） | 上一自然月，两端含 |
| 7 | `实时` | `realtime` | `t` | `t` | 1 | **今日** | 与 `今日实时` 同区间、不同键 |
| 8 | `未来14天` | `next_14d` | `t` | `t + 13d` | 14 | **今日** | 模块15 专属 |
| 9 | `未来30天` | `next_30d` | `t` | `t + 29d` | 30 | **今日** | 模块9 专属 |

**边界口径的精确说明（含/不含、是否以昨日为基准）**：

- **`上周`（唯一一个"自然周"口径）**：`ebk`/`api` 注释原文为「上一自然周（周一 ~ 周日）」（`api:147`）。实现为
  `monday = t - timedelta(days=t.weekday())` → `weekday()` 中 **周一=0 … 周日=6**，故 `monday` 是**本周一**；
  `start = monday - 7d` = **上周一**，`end = monday - 1d` = **上周日**。
  两端**都含**（闭区间）。**基准是「今日」，不是「昨日」** —— 即使 `t` 是周一，`start` 也是「上周一」而非「今天」。
- **`过去7天` / `过去30天`**：基准是**昨日**（`end = t - 1d`），`start = end - 6d` / `end - 29d`，两端都含。与 `api:146`/`api:148` 的文档串「昨日前推 7 个自然日（昨日-6 ~ 昨日，含 7 天）」「昨日前推 30 个自然日（昨日-29 ~ 昨日，含 30 天）」一致。
- **`昨日`**：严格 `t - 1day`（自然日减法，非工作日推算）。
- **`今日实时` / `实时`**：`start == end == t`。
- **`上月`**：`first_this = t.replace(day=1)`；`last_prev = first_this - 1d`（= 上月最后一日）；返回 `(last_prev.replace(day=1), last_prev)`。两端都含。**基准是「今日」**（非昨日）。注意该分支是函数**末尾的兜底 return**，没有 `if key == "last_month"` 判断（`api:170-173`）；`key` 只可能是上表 9 个值之一，故语义等价。
- **`未来14天` / `未来30天`**：`start = t`（含今日），`end = t + 13d` / `t + 29d`，两端都含。
- **分支判定顺序**（复现必须一致）：`yesterday` → (`today_realtime`, `realtime`) → `last_7d` → `last_week` → `last_30d` → `next_14d` → `next_30d` → 兜底 `last_month`（`api:155-173`）。
- `key` 的取值链路：`WINDOW_KEYS.get(normalize_window(window))`（`api:154`）—— 先规范化成中文名，再查内部键。

### 1.5 窗口 → 日期占位符替换表 `window_date_ctx`

`api:176-201` 逐字抄录：

```python
def window_date_ctx(window: str, today: Optional[Any] = None) -> dict[str, str]:
    t = date.today() if today is None else (
        date.fromisoformat(today) if isinstance(today, str) else today
    )
    start, end = compute_window_range(window, t)
    fmt = "%Y-%m-%d"
    ch = normalize_window(window)
    return {
        "date": end.strftime(fmt),
        "startDate": start.strftime(fmt),
        "endDate": end.strftime(fmt),
        "statDate": end.strftime(fmt),
        "yesterday": (t - timedelta(days=1)).strftime(fmt),
        "today": t.strftime(fmt),
        "window": ch,
        "window_key": WINDOW_KEYS[ch],
    }
```

### 2.2 完整实现原文

`api:346-382` 逐字抄录：

```python
    def _guard_placeholders(self, api_def: dict, ctx: dict) -> None:
        """占位符残留守卫（t12，兼容保护；先于任何请求重放执行）。

        目的：防「静默错数据」——旧采集流无窗口上下文时，defs 模板里的
        ``{startDate}``/``{endDate}`` 等会被替换成空串或原样残留并发送到平台，
        服务端可能返回语义错误的数据且 status=200。守卫规则：

        - 模板（url / params / body）中出现的 ``{xxx}`` 必须在 ctx 有非 None 值，
          否则抛 :class:`ApiCollectError`（视为「未校准」，上层照常降级浏览器）；
        - 渲染（替换）后仍残留 ``{xxx}``（未知占位符）同样抛错。

        0 回归口径：旧流此前这些 defs 以 405/错误响应失败并计入降级，守卫将其
        归类为 ApiCollectError（未校准），失败语义一致、不劣化，且绝不带
        空日期/占位符原文请求平台。
        """
        parts = [str(api_def.get("url") or "")]
        params = api_def.get("params")
        if isinstance(params, dict):
            parts.append(json.dumps(params, ensure_ascii=False))
        body = api_def.get("body")
        if body is not None:
            parts.append(json.dumps(body, ensure_ascii=False) if not isinstance(body, str) else body)
        template = "\n".join(parts)

        for token in dict.fromkeys(_PLACEHOLDER_RE.findall(template)):
            if token not in self._SUB_KEYS:
                raise ApiCollectError(
                    f"api_def 含未知占位符 {{{token}}}（视为未校准，将降级浏览器兜底）")
            if ctx.get(token) is None:
                raise ApiCollectError(
                    f"占位符 {{{token}}} 缺少窗口/上下文值（视为未校准，将降级浏览器兜底）")

        rendered = self._apply_placeholders(template, self._build_subs(ctx))
        residual = _PLACEHOLDER_RE.findall(rendered)
        if residual:
            raise ApiCollectError(
                f"api_def 占位符 {{{residual[0]}}} 渲染后仍残留（视为未校准，将降级浏览器兜底）")
```

### 2.3 复现规格

**检查哪些字段**（`api:361-368`）：

| 序 | 字段 | 取值方式 | 并入方式 |
|---|---|---|---|
| 1 | `url` | `str(api_def.get("url") or "")` —— `None`/`""` 都变 `""`，但**任何非空值先 `str()`** | `parts[0]` |
| 2 | `params` | 仅当 `isinstance(params, dict)` 时 → `json.dumps(params, ensure_ascii=False)` | `parts[1]` |
| 3 | `body` | 仅当 `body is not None` 时 → 若**不是** `str` 则 `json.dumps(body, ensure_ascii=False)`；**是** `str` 则原样 | `parts[2]` |

`template = "\n".join(parts)`（`api:368`）。即：等价于对 `url` + `params序列化` + `body序列化` 三段的并集做全量扫描。

**三步判定**（顺序固定）：

1. **未知占位符**：对 `dict.fromkeys(_PLACEHOLDER_RE.findall(template))`（**去重且保序**，`api:370`）的每个 `token`，若 `token not in self._SUB_KEYS` → 抛错。消息原文：
   `f"api_def 含未知占位符 {{{token}}}（视为未校准，将降级浏览器兜底）"`
   （`{{{token}}}` 在 f-string 中渲染为 `{token}`，如 `{foo}`）
2. **缺少上下文值**：若 `ctx.get(token) is None` → 抛错。消息原文：
   `f"占位符 {{{token}}} 缺少窗口/上下文值（视为未校准，将降级浏览器兜底）"`
   注意：判据是 **严格 `is None`**，`""`（空串）、`0`、`False` 都**不**触发（`api:374`）。
3. **渲染后残留**：`rendered = self._apply_placeholders(template, self._build_subs(ctx))`，再 `_PLACEHOLDER_RE.findall(rendered)`；若 `residual` 非空 → 抛错，只报**第一个**残留 token。消息原文：
   `f"api_def 占位符 {{{residual[0]}}} 渲染后仍残留（视为未校准，将降级浏览器兜底）"`

**抛什么异常**：`collectors.api_collector.ApiCollectError`（定义 `api:57-58`：`class ApiCollectError(Exception): """规则缺失、网络失败、解析失败等（非登录类）。"""`）。

**上游如何处置**：`api:561-567` 捕获 `ApiCollectError` → 计入 `failed_count`、把 `{"name","ok":False,"error":str(exc),"status_code":None,"url":api_def.get("url")}` 放进 `responses`；`ebk:773-778` 捕获后**降级浏览器通道**。

**`_SUB_KEYS` 与 `_build_subs` 的相互作用（复现要点）**：
- 守卫的成员检查用**静态常量** `self._SUB_KEYS`（9 个键，`api:302-303`），**不是** `ctx.keys()`。因此即使 `ctx` 里额外传了键，模板中出现它也会被判「未知占位符」。
- `{statDate}`、`{yesterday}`、`{today}` 在 `_SUB_KEYS` 中；在 `collect_sub_module` 路径上它们由 `window_date_ctx` 提供（`api:523`），故不会触发第 2 步。但若从别的路径调用 `request_api` 且 `ctx` 无这些键 → 第 2 步抛错。
- `{hotel_id}`：单店账号时 `ctx["hotel_id"] is None`（`ebk:519-521`）→ 第 2 步抛错。**当前规则中无任何 def 使用 `{hotel_id}`**（见 §3.7 统计），故生产中不触发。
- 第 3 步在正常情况下**不可达**：第 1、2 步已保证所有 token ∈ `_SUB_KEYS` 且 `ctx[token] is not None`，而 `_build_subs` 对非 `None` 值一定产出 `str(...)`，`_apply_placeholders` 用 `str.replace` 全量替换，故残留只可能来自「替换值本身含 `{xxx}`」。属于纵深防御。

```python
    """向 URL 追加单个 query 参数；已存在同名参数则不重复追加。"""
    sep = "&" if "?" in url else "?"
```

### 3.7 `body_by_window` 的用法

**代码**（`api:399-407`，逐字抄录见 §3.2）。精确语义：

1. **先**做占位符替换：`body = self._substitute_deep(body, self._build_subs(ctx))`（`api:402`）。
2. **再**取窗口覆盖表（`api:405`）：

```python
            win_override = (api_def.get("body_by_window") or {}).get(ctx.get("window")) or {}
```

   查表键 = `ctx.get("window")`，即 **窗口中文名**（由 `window_date_ctx` 的 `window` 提供，`api:199`；`merged` 合并后 `ctx["window"]` 可用）。
3. **仅当** `win_override` 为真值**且** `isinstance(body, dict)` 时做**浅合并**：
   `body = {**body, **win_override}` —— **只覆盖顶层键**，不递归、不删除原键（`api:406-407`）。
4. 若 `body` 是 `str`（表单模板）→ 覆盖**被静默忽略**（`isinstance(body, dict)` 为假）。
5. 若窗口中文名不在 `body_by_window` 中 → `win_override = {}` → 不覆盖（保留 `body` 原值）。
6. 覆盖发生在 `headers["content-type"]` 判定**之前**（`api:408` 在其后），且**不影响** `isinstance(body, str)` 的分支选择（dict 仍是 dict）。

**哪 2 条接口使用**（脚本实测，`"body_by_window"` 在 `rulesjson` 中出现 **2** 次）：

| 页 | def `name` | `method` | `url` |

| `竞争圈动态` | `getCompetingRankSell` | `POST` | `https://ebooking.ctrip.com/restapi/soa2/24588/getCompetingRank` |
| `竞争圈动态` | `getCompetingRankFlow` | `POST` | `https://ebooking.ctrip.com/restapi/soa2/24588/getCompetingRank` |

两条的 `body_by_window` 内容**完全相同**，键 = 窗口中文名，逐字抄录：

```json

    "dateType": 1
  },
  "今日实时": {
    "dateType": 2
  },
  "实时": {
    "dateType": 2
  },
  "上周": {
    "dateType": 3
  }
}
```

### 3.10 登录失效三路检测（精确字符串）

`api:429-447` 逐字抄录：

**第 ③ 路的完整判定函数** `api:69-90` 逐字抄录：

```python
def _login_marker_in_body(body: Any) -> bool:
    """判断请求响应的 body 是否含登录失效/登录页特征。"""
    if body is None:
        return False
    if isinstance(body, str):
        txt = body
    else:
        try:
            txt = json.dumps(body, ensure_ascii=False)
        except (TypeError, ValueError):
            return False
    low = txt.lower()
    # 明确的登录失效提示
    for marker in _LOGIN_BODY_MARKERS:
        if marker in txt:
            return True
    # 登录页跳转特征：body 为 HTML 登录页（含 html/doctype 与登录标记）
    if ("<html" in low or "<!doctype" in low or "登录" in txt) and any(
        m in low for m in _LOGIN_URL_MARKERS
    ):
        return True
    return False
```

精确子规则：
- `body is None` → `False`（`api:71-72`）。
- `body` 是 `str` → `txt = body`；否则 `json.dumps(body, ensure_ascii=False)`（`api:73-79`）。
- **子规则 A（明确失效提示）**：`_LOGIN_BODY_MARKERS` 三个中文串任一**在 `txt` 中出现**（**大小写敏感**，中文无大小写问题）→ `True`（`api:82-84`）。
- **子规则 B（HTML 登录页特征）**：`("<html" in low or "<!doctype" in low or "登录" in txt)` 为真 **且** `_LOGIN_URL_MARKERS` 中任一 marker 在 `low` 中出现 → `True`（`api:86-89`）。注意前两项用**小写化**后的 `low`，第三项 `"登录" in txt` 用原文。
- 其余 → `False`。

**`ok` 判定**：`ok = status < 400`（`api:447`）—— 即 3xx（未被上一路拦下的）与 2xx 都算 `ok=True`。

## 4. 字段提取 `json_get`

### 4.1 实现原文

`rules:379-400` 逐字抄录：

```python
def json_get(obj, path: str):
    """点号路径取值，支持 [0] 数组下标；取不到返回 None。

    逻辑与 collectors/ebooking.py 的 ``_json_get`` 一致：
    ``path`` 用 ``.`` 分段，段形如 ``[N]`` 时按数组下标取；其余按 dict 键取。
    """
    cur = obj
    for part in path.split("."):
        if part.startswith("[") and part.endswith("]"):
            try:
                idx = int(part[1:-1])
            except ValueError:
                return None
            if isinstance(cur, list) and idx < len(cur):
                cur = cur[idx]
            else:
                return None
        elif isinstance(cur, dict) and part in cur:
            cur = cur[part]
        else:
            return None
    return cur
```

### 4.2 精确语义（逐行规格）

1. `path.split(".")` —— **以英文句点分段**。因此：
   - `"a.b.c"` → `["a", "b", "c"]`
   - `"data.[0].tip1"` → `["data", "[0]", "tip1"]` ← **`rulesjson` 中数组下标的实际写法**（带前置点）
2. 对每个 `part`：
   - **若 `part` 以 `[` 开头且以 `]` 结尾** → 取 `int(part[1:-1])` 作下标：
     - `int()` 抛 `ValueError`（如 `"[abc]"`、`"[]"`）→ **立即 `return None`**。
     - 仅当 `isinstance(cur, list) and idx < len(cur)` → `cur = cur[idx]`；否则 **`return None`**。
     - **负下标可用**：`idx < len(cur)` 对负数是真（如 `-1 < len`），故 `"[-1]"` 会取到 `cur[-1]`（Python 负索引），`"[-99]"` 在长度不足时抛 `IndexError`（**未被捕获**）。这是需要复现或显式收紧的边界行为。
   - **否则若 `isinstance(cur, dict) and part in cur`** → `cur = cur[part]`。
   - **否则 `return None`**。
3. 全部段走完 → `return cur`。
4. **取不到一律返回 `None`，从不抛异常**（除上述负下标越界）。

### 4.3 关键"坑"：`data[0].x` 不支持

### 5.3 `_is_empty_value` —— 「明确无数据」的取值判定

`api:491-498` 逐字抄录：

```python
    @staticmethod
    def _is_empty_value(v: Any) -> bool:
        """「明确无数据」判定：None / 空串 / 空列表 / 空 dict。"""
        if v is None:
            return True
        if isinstance(v, (str, list, dict)):
            return len(v) == 0
        return False
```

**算作"空"的值**（穷举）：`None`、`""`（空串）、`[]`（空列表）、`{}`（空 dict）。
**不算空的值**：`0`、`0.0`、`False`、`"0"`、`" "`（含空白字符的串长度非 0）、`[0]`、`{"a":1}`、任意非 `None` 的数字/布尔。

## 6. DOM 提取四前缀

### 6.1 前缀常量原文

`ebk:70-77` 逐字抄录：

```python
# DOM 提取 path 前缀（浏览器兜底通道）：
#   css:<selector>  → 首个可见元素文本；text:<关键词> → 正文「关键词+数值」正则
#   js:<表达式>     → page.evaluate（须可 JSON 序列化）；table:<n> → 第 n 张表(0 起)
#   无前缀          → 视为关键词，走 text: 逻辑
_FIELD_PATH_CSS = "css:"
_FIELD_PATH_JS = "js:"
_FIELD_PATH_TABLE = "table:"
_FIELD_PATH_TEXT = "text:"
```

### 6.2 实现原文

`ebk:852-900` 逐字抄录：

```python
    def _extract_module_dom(self, page, sub_module: dict) -> dict[str, Any]:
        """按 ``sub_module.apis[*].fields[*].path`` 从 DOM 提取模块数据（浏览器兜底）。

        字段 path 约定（见模块级 ``_FIELD_PATH_*`` 常量）：
        - ``css:<selector>``：首个可见元素文本；
        - ``text:<关键词>`` / 裸关键词：正文「关键词+数值」正则；
        - ``js:<表达式>``：``page.evaluate`` 求值（须可 JSON 序列化）；
        - ``table:<n>``：第 n 张表（0 起）整表（二维字符串数组）。
        """
        try:
            body_text = page.locator("body").inner_text(timeout=10_000)
        except Exception:  # noqa: BLE001
            body_text = ""
        tables = self._extract_tables(page)
        payload: dict[str, Any] = {}
        for entry in sub_module.get("apis") or []:
            for field in entry.get("fields") or []:
                label = field.get("label")
                path = str(field.get("path") or "").strip()
                if not label or label in payload:
                    continue
                if path.startswith(_FIELD_PATH_CSS):
                    loc = page.locator(path[len(_FIELD_PATH_CSS):].strip()).first
                    try:
                        if loc.count() > 0 and loc.is_visible():
                            payload[label] = loc.inner_text(timeout=3000).strip()
                    except Exception:  # noqa: BLE001
                        continue
                elif path.startswith(_FIELD_PATH_JS):
                    try:
                        payload[label] = page.evaluate(path[len(_FIELD_PATH_JS):].strip())
                    except Exception:  # noqa: BLE001
                        continue
                elif path.startswith(_FIELD_PATH_TABLE):
                    try:
                        idx = int(path[len(_FIELD_PATH_TABLE):].strip())
                    except ValueError:
                        continue
                    if 0 <= idx < len(tables):
                        payload[label] = tables[idx]
                else:
                    kw = (path[len(_FIELD_PATH_TEXT):].strip()
                          if path.lower().startswith(_FIELD_PATH_TEXT) else path)
                    if not kw:
                        continue
                    m = re.search(re.escape(kw) + r"\s*[:：]?\s*([-\d,]+(?:\.\d+)?\s*%?)", body_text)
                    if m:
                        payload[label] = m.group(1).strip()
        return payload
```

### 6.3 逐前缀规格

**公共前置**：
- `body_text`：`page.locator("body").inner_text(timeout=10_000)`；抛异常 → `""`（`ebk:861-864`）。
- `tables`：**无条件先算**（`ebk:865`，即便没有 `table:` 字段也会执行 `_extract_tables`）。
- 遍历 `sub_module.apis[*].fields[*]`；`label` 为空或**已存在** → `continue`（**同 label 首个命中优先**，`ebk:871-872`）。
- `path = str(field.get("path") or "").strip()` —— **先 `strip()` 再判前缀**（`ebk:870`）。

| 前缀 | 匹配方式 | 取值 | 返回结构 | 失败行为 |
|---|---|---|---|---|
| `css:` | `path.startswith("css:")` —— **大小写敏感** | `loc = page.locator(<前缀后 strip 的剩余串>).first`；`loc.count() > 0 and loc.is_visible()` → `loc.inner_text(timeout=3000).strip()` | `str`（已 `strip()`） | `count()==0` 或不可见 → **不写入该 label**（静默跳过）；抛异常 → `continue`（`ebk:873-879`） |
| `js:` | `path.startswith("js:")` —— **大小写敏感** | `page.evaluate(<前缀后 strip 的剩余串>)` | `page.evaluate` 的返回值，**须可 JSON 序列化**（`ebk:858` 原文） | 抛异常 → `continue`（`ebk:880-884`） |
| `table:` | `path.startswith("table:")` —— **大小写敏感** | `idx = int(<前缀后 strip 的剩余串>)`；`0 <= idx < len(tables)` → `tables[idx]` | `list[list[str]]`（二维字符串数组，第 `n` 张表，**0 起**） | `int()` 抛 `ValueError` → `continue`；`idx` 越界（含负数）→ **不写入**（`ebk:885-891`） |
| `text:` | `path.lower().startswith("text:")` —— **大小写不敏感**（唯一一个大小写不敏感的） | `kw = path[5:].strip()` | `m.group(1).strip()`，即 `str` | `kw` 为空 → `continue`；正则不匹配 → **不写入**（`ebk:893-899`） |
| 无前缀（裸关键词） | `else` 分支 | `kw = path`（**原样，不 strip 前后缀**，但 `path` 本身已在 `ebk:870` strip 过） | 同 `text:` | 同 `text:` |

**`text:` / 裸关键词的完整正则**（`ebk:897`）逐字抄录：

```python
                    m = re.search(re.escape(kw) + r"\s*[:：]?\s*([-\d,]+(?:\.\d+)?\s*%?)", body_text)
```

- `re.escape(kw)` —— 关键词**字面量**匹配（正则元字符被转义）。
- `r"\s*[:：]?\s*"` —— 允许任意空白 + **可选的半角 `:` 或全角 `：`** + 任意空白。
- `([-\d,]+(?:\.\d+)?\s*%?)` —— 捕获组：`[-\d,]+`（数字/负号/千分位逗号，至少 1 个）+ 可选小数部分 `(?:\.\d+)?` + 可选尾随空白 + 可选 `%`。
- 取 `m.group(1).strip()`；**只取第一个匹配**（`re.search`，非 `findall`）。

**`table:` 的表格抽取实现** `ebk:488-510` 逐字抄录：

```python
    @staticmethod
    def _extract_tables(page) -> list[list[list[str]]]:
        """抽取页面所有表格为二维字符串数组（一次 evaluate 批量取回，减少协议往返）。"""
        try:
            tables = page.evaluate(
                """() => {
                    const out = [];
                    for (const t of document.querySelectorAll('table')) {
                        const rows = [];
                        for (const tr of t.querySelectorAll('tr')) {
                            const cells = Array.from(tr.querySelectorAll('th, td'))
                                .map(c => (c.innerText || '').trim());
                            if (cells.some(c => c !== '')) rows.push(cells);
                        }
                        if (rows.length) out.push(rows);
                    }
                    return out;
                }"""
            )
            return tables or []
        except Exception as exc:  # noqa: BLE001
            logger.warning("表格抽取失败: {}", exc)
            return []
```

**`table:` 返回结构的精确定义**：
- 外层 `list`：页面中每张**有内容**的 `<table>`（`document.querySelectorAll('table')` 顺序，按文档序）。
- 只保留 `rows.length > 0` 的表（`if (rows.length) out.push(rows)`）。
- 每行 = 该 `<tr>` 内所有 `th, td` 的 `innerText` 经 `.trim()` 后的数组。
- **丢弃全空行**（`if (cells.some(c => c !== '')) rows.push(cells)`）。
- 单元格值：`(c.innerText || '').trim()` —— **字符串**，`innerText` 为空/`null` 时回退 `""`。
- 失败 → `[]`（并打 `logger.warning("表格抽取失败: {}", exc)`）。
- 因此 `table:<n>` 取到的是 `tables[n]` = `list[list[str]]`（二维字符串数组）。**注意 `n` 的编号是"有内容的表"的序号，不是 DOM 中第 n 个 `<table>`。**

### 6.4 与 API 通道 `path` 的区别（重要）

- **API 通道**（`json_get`）：`path` 是 **JSON 点号路径**（如 `data.[0].tip1`）。
- **DOM 通道**（`_extract_module_dom`）：`path` 是 **前缀 + 参数**（`css:`/`js:`/`text:`/`table:` 或裸关键词）。
- 两者共用**同一份** `sub_module.apis[*].fields[*].path` 字段，靠前缀区分通道语义：`rulesjson` 中所有 `path` 都是 JSON 路径形式（无 `css:`/`js:`/`text:`/`table:` 前缀），因此**DOM 兜底通道当前实际会把所有 path 当作裸关键词走 `text:` 正则**。这是一个需要重写时明确决策的点。

```python
def hotel_code(hotel: dict | int) -> str:
    """hotel 行 dict 或整数 id → 'h001' 形式代码。"""
    hid = hotel.get("id") if isinstance(hotel, dict) else hotel
    return f"h{int(hid):03d}"


def hotel_dir_name(account: Optional[dict], hotel: dict | int) -> str:
    """存储目录名：账号别名优先（accounts.alias），多店账号追加 hotel_id 防冲突；
    无账号/无别名回退 hotel_code（h001，兼容旧行为）。"""
    alias = (account or {}).get("alias")
    if alias:
        base = safe_filename(str(alias))
        if (account or {}).get("is_multi"):
            hid = hotel.get("id") if isinstance(hotel, dict) else hotel
            base = f"{base}_h{int(hid or 0):03d}"
        return base
    return hotel_code(hotel)
```

**精确算法**：
1. `alias = (account or {}).get("alias")`。
2. `alias` 为真 → `base = safe_filename(str(alias))`（**别名也要安全化**）。
3. 若 `account.get("is_multi")` 真 → `base = f"{base}_h{int(hid or 0):03d}"`，其中 `hid = hotel["id"]`（dict）或 `hotel`（int）。**注意 `int(hid or 0)`：`hid` 为 `0`/`None`/`""` 时都变 `0` → `_h000`**。
4. `alias` 为假 → 回退 `hotel_code(hotel)` = `f"h{int(hid):03d}"`（如 `h001`）。
5. `hotel_code` 对 `None` 会抛 `TypeError`（`int(None)`）—— 调用方须保证 `hotel` 有效。

### 8.9 `to_relative` / `from_relative` 精确实现

`layout:84-102` 逐字抄录：

```python
def to_relative(path: Optional[Path | str]) -> Optional[str]:
    """绝对/相对路径 → 入库用相对路径字符串（相对 BASE_DIR）；空返回 None。"""
    if not path:
        return None
    p = Path(path)
    if p.is_absolute():
        try:
            return str(p.relative_to(BASE_DIR))
        except ValueError:
            return str(p)
    return str(p)


def from_relative(path: Optional[Path | str]) -> Optional[Path]:
    """入库路径字符串 → 绝对 Path（相对 BASE_DIR），供读取侧统一解析。"""
    if not path:
        return None
    p = Path(path)
    return p if p.is_absolute() else BASE_DIR / p
```

**`to_relative` 精确语义**：
1. `if not path: return None` —— **假值即返回 `None`**：`None`、`""`、以及 `Path("")`（`Path("")` 真值为 `True`… 实际 `bool(Path(""))` 为 `True`，因为 `Path` 未定义 `__bool__`/`__len__`；但 `None`/`""(str)` 为假）→ 返回 `None`。
2. `p = Path(path)`。
3. 绝对路径 → `str(p.relative_to(BASE_DIR))`；若**不在 `BASE_DIR` 下** → `ValueError` → **原样返回绝对路径字符串** `str(p)`（不报错、不截断）。
4. 相对路径 → 原样 `str(p)`。
5. **返回类型恒为 `str` 或 `None`**（不是 `Path`）。
6. **不规范化**（不 `resolve()`、不去 `..`）；Windows 上 `str(WindowsPath)` 用反斜杠分隔符。

**`from_relative` 精确语义**：
1. `if not path: return None`。
2. 绝对路径 → 原样返回 `Path`。
3. 相对路径 → `BASE_DIR / p`（**不做存在性校验**）。
4. **返回类型恒为 `Path` 或 `None`**。
→ 两者**互逆**（对 `BASE_DIR` 下的绝对路径成立）；跨机迁移时依赖 `BASE_DIR` 一致。

## 10. `collectors/rules.py` 校验逻辑清单

### 10.1 异常与统一断言

`rules:95-107` 逐字抄录：

```python
class ApiRulesError(ValueError):
    """规则文件缺失或非法时抛出；消息指明具体问题（如 pages.经营报告.url 缺失）。"""


def _default_rules_path() -> Path:
    """规则文件默认路径：config/api_rules.json。"""
    return Config.CONFIG_DIR / "api_rules.json"


def _require(cond: bool, message: str) -> None:
    """校验失败统一抛 ApiRulesError。"""
    if not cond:
        raise ApiRulesError(message)
```

→ **异常类型 = `ApiRulesError`，继承自 `ValueError`**（`rules:95`）。**所有**校验失败都经 `_require` 抛出。

### 10.2 报错信息的路径定位写法（逐字）

路径 `loc` 由字符串拼接逐层构造，**用英文句点 `.` 连接、数组下标用 `[n]`**：

| 层级 | 构造表达式 | 证据 | 示例消息（逐字） |
|---|---|---|---|
| 顶层 | `f"{path}"` | `rules:310-311` | `<path>: 顶层结构应为对象(dict)`、`<path>: 缺少键 pages` |
| `pages` 容器 | `f"{path}.pages"` | `rules:313` | `<path>.pages: 应为对象(dict)` |
| 单页 | `f"{path}.pages.{page_name}"` | `rules:315` | `<path>.pages.经营报告.url: 应为非空字符串` |
| 页内字段 | `f"{loc}.<键>"` | `rules:206` 等 | `<path>.pages.经营报告.min_indicators: 应为不小于 0 的整数` |
| `modules` 条目 | `f"{loc}.modules.{mod_name}[{j}]"` | `rules:220-223` | 见下 |

### 10.4 加载与缓存

`rules:318-354` 逐字抄录：

```python
def load_api_rules(path: Optional[Path] = None) -> dict:
    """加载并校验接口规则，返回解析后的 dict。

    校验通过才返回；文件缺失、JSON 非法、结构不符均抛 :class:`ApiRulesError`。
    缺省 ``path`` = ``Config.CONFIG_DIR / "api_rules.json"``。
    """
    p = Path(path) if path is not None else _default_rules_path()
    if not p.exists():
        logger.warning("接口规则文件缺失: {}", p)
        raise ApiRulesError(f"规则文件不存在: {p}")
    try:
        with open(p, "r", encoding="utf-8") as f:
            data = json.load(f)
    except json.JSONDecodeError as exc:
        raise ApiRulesError(f"规则文件 JSON 解析失败: {p}（{exc}）") from exc
    _validate(data, p)
    return data


def get_api_rules(path: Optional[Path] = None) -> dict:
    """读取规则（带模块级缓存 + mtime 热加载）。

    首次或文件修改时间变化时重读并重校验；规则文件本身不存在时抛 :class:`ApiRulesError`。
    """
    p = Path(path) if path is not None else _default_rules_path()
    key = str(p.resolve())
    try:
        mtime = p.stat().st_mtime
    except OSError:
        # 文件不存在：让 load_api_rules 打印告警并抛错
        return load_api_rules(p)
    cached = _RULES_CACHE.get(key)
    if cached is not None and cached[0] == mtime:
        return cached[1]
    data = load_api_rules(p)  # 加载 + 校验；出错会抛 ApiRulesError
    _RULES_CACHE[key] = (mtime, data)
    return data
```

**载荷异常消息原文**：
- 文件不存在：`f"规则文件不存在: {p}"`（`rules:327`），并先 `logger.warning("接口规则文件缺失: {}", p)`（`rules:326`）。
- JSON 非法：`f"规则文件 JSON 解析失败: {p}（{exc}）"`（`rules:332`）。
- 缓存键：`str(p.resolve())`（**绝对路径**，`rules:343`）；缓存值：`(mtime, data)`（`rules:353`）；`mtime` 相等即命中（`rules:350`）。

### 10.5 `extract_indicators`（legacy 页级指标提取）

`rules:403-438` 逐字抄录：

```python
def extract_indicators(payloads: list[dict], api_modules: dict) -> tuple[dict, dict]:
    """从接口响应列表提取指标。

    ``payloads``: ``[{'name': api名, 'url': url, 'body': dict}, ...]``；
    ``api_modules``: 与 ``api_rules.json`` 的 ``pages.<page>.modules`` 同构：
        ``{模块名: [{"api": 关键词, "fields": [{"path":..., "label":...}, ...]}, ...]}``

    返回 ``(平面指标 dict, 按模块分组 dict)``。
    匹配规则：任一 payload 的 ``url``/``name`` 小写后包含 api 关键词（与旧
    ``_extract_indicators_from_api`` 语义一致）；同 label 首个命中优先（不覆盖）。
    """
    flat: dict = {}
    modules: dict = {}
    for payload in payloads or []:
        url = str(payload.get("url", "")).lower()
        name = str(payload.get("name", "")).lower()
        body = payload.get("body")
        haystack = f"{url} {name}"
        for module_name, entries in (api_modules or {}).items():
            for entry in entries or []:
                keyword = str(entry.get("api", "")).lower().strip()
                if not keyword or keyword not in haystack:
                    continue
                mod = modules.setdefault(module_name, {})
                for field in entry.get("fields", []):
                    label = field.get("label")
                    if label in flat:
                        continue  # 优先保留第一个命中
                    val = json_get(body, field.get("path"))
                    if val is not None:
                        flat[label] = val
                        mod[label] = val
    # 经营总览 = 全部指标（对应整页截图）
    if flat:
        modules["经营总览"] = dict(flat)
    return flat, modules
```

**精确语义**：
- 匹配干草堆 = `f"{url} {name}"`（**两者都已 `.lower()`**，中间一个空格）；关键词 = `str(entry.get("api", "")).lower().strip()`；`keyword not in haystack` → 跳过（**子串包含**，非正则）。
- 同 label **首个命中优先**（`if label in flat: continue`）。
- `json_get` 返回 `None` → 不写入。
- 收尾：若 `flat` 非空，注入 `modules["经营总览"] = dict(flat)`（**`经营总览` 是字面量模块名**）。

  1. 本函数自身**没有** API 直连逻辑 —— 「API 直连优先 → 浏览器兜底」发生在它所调用的 `EbookingCollector._collect_one_module` 内（`ebk:761-781`）。文档串描述的是**被调方**的行为，容易被误读为「本函数实现了 API 直连」。
  2. 返回结构**多出一个文档未声明的 `channel` 键**，值恒为 `"module"`（`api:649`）。
  3. 参数 `headless` 只透传给 `EbookingCollector`（浏览器兜底用），**对 API 直连无影响**。

### 漂移 8：`normalize_window` 报错消息的"内部键别名"列表包含 `next_14d`

- **实现**（`api:136`）：`f"内部键别名: {', '.join(sorted(set(WINDOW_NAMES) - {'next_30d'}))}）"`
- **实测输出**：仅排除 `next_30d`，故列表为 `last_30d, last_7d, last_month, last_week, next_14d, realtime, today_realtime, yesterday`（8 项，含 `next_14d`）

### 漂移 10：`_SUB_KEYS` 含 `{date}`，但 `merged` 中 `date` 已被窗口末日覆盖

- **代码**：`merged = {**ctx, **window_date_ctx(window, ctx.get("date"))}`（`api:523`），而 `window_date_ctx["date"] = end`（`api:194`）。
- **后果**：模板里 `{date}` 渲染出的是**窗口末日**，**不是采集日**；采集日只在 `{today}`（= `t`，来自 `window_date_ctx["today"]`，`api:198`）以及 `window_date_ctx` 的 `today` 实参中体现。
- **文档串佐证**：`api:179` 原文即「``date`` / ``statDate``：窗口末日（单日窗口 = 该日）——``{date}`` 的窗口语义」——**代码与文档一致**，但容易与 `ctx["date"]`（采集日，`ebk:523`）混淆。重写时务必区分这两个 `date`。

### 漂移 11：`json_get` 对负下标的行为未定义（潜在 `IndexError`）

- **代码**（`rules:392`）：`if isinstance(cur, list) and idx < len(cur):` —— 负数 `idx` 也满足 `idx < len(cur)`。
- **后果**：`"[-1]"` 在非空 list 上正常返回末元素；`"[-99]"` 在 list 长度不足时执行 `cur[-99]` → **抛 `IndexError`**（未被捕获，违反 `rules:380` 文档串「取不到返回 None」的承诺）。
- **证据**：`rules:379-400`；文档串 `rules:380`：「点号路径取值，支持 [0] 数组下标；取不到返回 None。」
- **判定**：当前 `rulesjson` 中所有下标均为非负（`[0]`/`[1]`/`[2]`），故生产上不触发。重写时应显式处理 `idx < 0`（如 `0 <= idx < len(cur)`），或原样保留并在文档中标注。

### 漂移 12：`_extract_module_dom` 与 `rulesjson` 的 `path` 写法不兼容

- **代码**（`ebk:852-900`）：DOM 通道按 `css:`/`js:`/`text:`/`table:` 前缀分派，**无前缀则当关键词走 `text:` 正则**。
- **实测**：`rulesjson` 中 `sub_modules[*].apis[*].fields[*].path` **全部**是 JSON 点号路径（如 `data.[0].tip1`、`sellRanksBO.[0].hotelName`），**无一条**带 DOM 前缀。
- **后果**：一旦 API 通道失败降级浏览器，`_extract_module_dom` 会把 `data.[0].tip1` 当作**关键词**去 `body_text` 里正则搜索 → 几乎必然搜不到 → `payload` 为空 → 状态落 `no_data`（`ebk:832`：「API 通道失败且浏览器无数据（明确无数据）」），**这是一个静默错误语义**：真实原因是"DOM 路径未校准"，却被标注为"明确无数据"。
- **证据**：`ebk:892-899`（else 分支）、`ebk:829-832`；`rulesjson` 全量 path 形态（§4.4 样例）
- **判定**：重写时必须为每个子模块显式区分「API 路径」与「DOM 路径」（或让 `no_data` 与「DOM 未校准」用不同状态），否则浏览器兜底会系统性地产出假 `no_data`。
