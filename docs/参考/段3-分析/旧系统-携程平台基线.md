## §0 一句话结论

**这套携程实现"能用"到「偶尔能拿到锚点店附近几家竞对的名称+价格+评分」，但它给出的是一张没有坐标、没有距离、没有店页 URL、没有房型、来源标签失真的扁平列表 —— 在 18 次有归档的真实采集里，只有 4 次拿到真酒店（2026-08-25），其余 12 次是优惠券假阳性、2 次是 0 家；因此它可作为「选择器与接口形状的考古标本」，不能作为「取数能力」继承。**

## §2 锚点定位（无 `_extract_anchor`；等价逻辑 = DB 优先 + 列表页兜底）

**重要澄清**：`ctrip.py` 中**不存在** `_extract_anchor`。等价逻辑由 2 个模块级/静态函数组成，且**顺序是 DB 优先，列表页兜底**（与 `base.py` 模板的字面顺序相反）。归档测试 `tests/test_ctrip_platform.py:99-151` 的类名 `CollectOrderTest` 与 docstring「DB 优先顺序:自家店(hotels 表有 ebk_hotel_id)不得访问列表页(免 30s 超时)」明确固化了该顺序。

### 2.1 取 `ebk_hotel_id`（首选路径）

`_hotel_id_from_db`（`ctrip.py:226-237`）原文：

```python
@staticmethod
def _hotel_id_from_db(anchor_name: str) -> str:
    """hotels 表 ebk_hotel_id 快捷入口(城市缺失/列表页失败时兜底)。"""
    try:
        from config import Config as _C
        from storage.db import Storage

        row = Storage(_C.DB_PATH).get_hotel_by_name(anchor_name)
        return str(row.get("ebk_hotel_id") or "") if row else ""
```

- SQL 语义：`Storage.get_hotel_by_name`（`storage/db.py:556-559`）= `SELECT * FROM hotels WHERE name=?` — **精确等值、无 LIKE、无归一化**。表名必须与 `config/compare_hotels.txt` 的 `酒店名` 字面一致（`OLD/config/compare_hotels.txt:1-5`：`隐欲民宿|莱州`、`盛铂仕丹酒店(青城山景区高铁站店)|都江堰`、`嫣杭民宿|开封`、`静荷民宿(蒙自市政府店)|蒙自`）。

### 2.2 未登记时的兜底路径（城市 sitemap → 列表页 → 首个 hotelId）

**第 1 步：城市名 → cityId**（`_resolve_city_id`，`ctrip.py:185-201`）

```python
@staticmethod
def _resolve_city_id(city_name: str) -> str:
    """城市名 → cityId;支持'莱州(烟台)'形式;进程级缓存。未命中返回 ''。"""
    name = (city_name or "").strip()
    if not name:
        return ""
    if name in _city_id_cache:
        return _city_id_cache[name]
    core = re.split(r"[（(]", name)[0].strip()
    for city, cid in _fetch_city_ids().items():
        c_core = re.split(r"[（(]", city)[0].strip()
        if c_core == core or (len(core) >= 2 and core in c_core) or (len(core) >= 2 and c_core in core):
            _city_id_cache[name] = cid
            logger.info("[ctrip] 城市 {} -> cityId={}", city, cid)
            return cid
    logger.warning("[ctrip] 城市列表里未找到: {}", name)
    return ""
```

```python
def _fetch_city_ids() -> dict[str, str]:
    """{城市全名: cityId}——m.ctrip 城市 sitemap(实测 2144 城;莱州(烟台)→3915)。失败返回 {}。"""
```

```python
LIST_PAGE_URL = "https://hotels.ctrip.com/hotels/list"       # ctrip.py:27

@staticmethod
def _build_list_url(anchor_name: str, city_id: str,
                    checkin: str = "", checkout: str = "") -> str:
    """列表页直达 URL(与美团 list.html 同位)。"""
    from urllib.parse import urlencode
    params: dict[str, str] = {"city": city_id or "1", "keyword": anchor_name}
    if checkin:
        params["checkin"] = checkin
    if checkout:
        params["checkout"] = checkout
    return LIST_PAGE_URL + "?" + urlencode(params)
```

### 4.1 `_on_response`：如何只读抓 JSON

```python
def _on_response(self, response) -> None:
    """拦截 JSON 接口响应（只读捕获，不伪造请求）。"""
```

### 4.2 命中接口后如何从 JSON 取价格：字段路径

**没有固定字段路径 —— 是纯键名启发式递归搜索。**`_scan_hotel_entries`（`ctrip.py:82-108`）原文：

```python
def _scan_hotel_entries(node, depth: int = 0, max_depth: int = 6):
    """递归找第一个"≥2 个 {名称, 价格}"的酒店条目列表(捕获 JSON 中)。"""
    if depth > max_depth:
        return []
    if isinstance(node, list):
        if node and all(isinstance(x, dict) for x in node):
            names = prices = 0
            for x in node:
                lk = {str(k).lower(): v for k, v in x.items()}
                if any(("name" in k or "title" in k) and isinstance(v, str) and len(v) >= 2
                       for k, v in lk.items()):
                    names += 1
                if any(("price" in k or "amount" in k) and isinstance(v, (int, float)) and v > 0
                       for k, v in lk.items()):
                    prices += 1
            if names >= 2 and prices >= 2:
                return node
        for item in node:
            r = _scan_hotel_entries(item, depth + 1, max_depth)
            if r:
                return r
    elif isinstance(node, dict):
        for v in node.values():
            r = _scan_hotel_entries(v, depth + 1, max_depth)
            if r:
                return r
    return []
```

## §5 距离与坐标（为什么 `distance_km` 恒为 `None`）

### 5.1 `distance_km` 在 ctrip.py 的赋值行

| 出现位置 | 原文 | 行号 |
|---|---|---|
| hits 条目 | `hits.append({"name": name, "url": "", "hotel_id": None, "coord": None, "coord_source": "", "distance_km": None})` | **`ctrip.py:401-402`** |
| quotes 条目 | `quotes.append({"name": name, "platform": "ctrip", "url": "", "distance_km": None, "price": price, ...})` | **`ctrip.py:403-404`** |

→ 两处都是**字面量 `None`**。`ctrip.py` 全文没有任何 `distance_km = <计算>`。

### 5.2 确凿因果链（7 步）

1. `_extract_nearby_hotels_dom` 抽取的是 `distance`（**中文文本**，如「距酒店直线1公里」），不是数值距离；且该选择器 `span[class*='text-ellipsis-suffix_titleText']`（`ctrip.py:475`）**从未命中**（18 条归档全为 `""`）。
2. 启发式兜底更直接把 `distance` 写死 `""`（`ctrip.py:543`）。
3. `collect_map_prices` 的 `result["hotels"]` 里保留 `distance` 文本键（`ctrip.py:371`）——但这是**文本**，且对下游无用。
4. `collect()` 转 hits/quotes 时**只读 4 个键**：`name` / `price` / `price_source` / `error`（`ctrip.py:399-407`）→ **`distance` 文本被彻底丢弃**，`hotels` 里的 `score`、`reviews`、`original_price`、`screenshot`、`raw` 也全部丢弃。
5. 平台**从不产出 `coord`**：`hits[i]["coord"]` 写死 `None`（`ctrip.py:401`），`anchor["coord"]` 写死 `None`（`ctrip.py:409-410`）。
6. `distance_km` 唯一的真实计算点是 `base._rank_hits`（`base.py:110-123`）：
   ```python
   if anchor_coord and h.get("coord"):
       from comparator.geo import haversine_km
       h["distance_km"] = round(haversine_km(anchor_coord[0], anchor_coord[1],
                                             h["coord"][0], h["coord"][1]), 2)
   else:
       h["distance_km"] = None
   ```
   而 `_rank_hits` 只被 `base.collect`（`base.py:51`）调用 → **模板被覆写 → 永不执行**。
7. `geo.py` 对携程**整体死代码**：`deep_find_coords`/`extract_coords_from_text` 只被 `base._extract_coords_from_page`（`base.py:159-173`）调用，后者只被 `base._fill_coords`（`base.py:102`）调用，后者只被 `base.collect`（`base.py:50`）调用；`best_coord`（`geo.py:90-92`）**全仓无任何调用**。`haversine_km` 的活调用点只有 `runner.py:48`（`_demo_payload` 演示数据）。

**完整因果句**：`ctrip` 既不抽坐标、也不算距离、更不调用 geo —— 三处独立断链中的**任何一处**都足以让 `distance_km` 恒为 `None`；实际是三处同时断。下游因此退化：`runner._merge_quotes` 的排序键对全部 ctrip 条目都是 `(True, 1e9)`（`runner.py:113`）→ 距离排序失效，退回平台返回顺序；`report.py:52/85` 的 `dist` 恒为 `""` → 报告里永远不显示距离。

### 5.3 `geo.deep_find_coords` 的实现与期望输入

`geo.py:18-60` 原文（关键部分）：

```python
_LAT_KEYS = ("lat", "latitude", "wgs84lat")                       # geo.py:18
_LNG_KEYS = ("lng", "lon", "longitude", "wgs84lng")               # geo.py:19

def _norm_coord(v: Any) -> Optional[float]:
    try:
        f = float(v)
    except (TypeError, ValueError):
        return None
    if not math.isfinite(f):
        return None
    return f                                                       # geo.py:22-29

def deep_find_coords(obj: Any) -> list[tuple[float, float]]:
    """递归深搜 JSON，找同时含 lat/lng 键的对象，返回 (lat, lng) 列表（去重）。"""
    found: list[tuple[float, float]] = []
    seen: set[tuple[float, float]] = set()

    def walk(node: Any, d: int) -> None:
        if d > 12:                                                 # 深度上限 12
            return
        if isinstance(node, dict):
            lat = lng = None
            for k, v in node.items():
                lk = str(k).lower()
                if lk in _LAT_KEYS:                                # 精确等值，非子串
                    lat = _norm_coord(v)
                elif lk in _LNG_KEYS:
                    lng = _norm_coord(v)
            if lat is not None and lng is not None and (-90 <= lat <= 90) and (-180 <= lng <= 180):
                pair = (round(lat, 6), round(lng, 6))
                if pair not in seen:
                    seen.add(pair); found.append(pair)
            for v in node.values():
                walk(v, d + 1)
        elif isinstance(node, list):
            for v in node:
                walk(v, d + 1)

    walk(obj, 0)
    return found
```

| 契约 | 内容 |
|---|---|
| 输入 | 任意 JSON 反序列化后的对象（`base.py:163` 传 `cap["body"]`，即 `response.json()` 的结果） |
| 期望结构 | **同一 dict 内**同时存在 lat 键与 lng 键；键名小写后必须**精确等于** `lat`/`latitude`/`wgs84lat` 与 `lng`/`lon`/`longitude`/`wgs84lng` 之一（**不做子串匹配**，所以 `positionLat`、`latStr` 都不认） |
| 值类型 | 任意可 `float()` 的东西（字符串 `"37.165587"` ✅ 可被接受） |
| 合法性 | `-90<=lat<=90` 且 `-180<=lng<=180` |
| 去重 | `(round(lat,6), round(lng,6))` |
| 顺序 | **深度优先、dict 按插入顺序** → 返回的**第一个**就是"JSON 里最先出现的坐标对" |
| 深度 | `d > 12` 停止 |

**文本坐标正则原文**（`geo.py:63-70`，备用路径 `base.py:167-170` 用）：

```python
_COORD_PAIR_RE = re.compile(
    r"""(?:["']?)(?:lat(?:itude)?|wgs84lat)(?:["']?)\s*[:=]\s*["']?(-?\d{1,2}\.\d{4,})["']?\s*[,;]\s*(?:["']?)(?:lng|lon|longitude|wgs84lng)(?:["']?)\s*[:=]\s*["']?(-?\d{1,3}\.\d{4,})["']?""",
    re.IGNORECASE,
)
_COORD_PAIR_RE2 = re.compile(
    r"""(?:["']?)(?:lng|lon|longitude|wgs84lng)(?:["']?)\s*[:=]\s*["']?(-?\d{1,3}\.\d{4,})["']?\s*[,;]\s*(?:["']?)(?:lat(?:itude)?|wgs84lat)(?:["']?)\s*[:=]\s*["']?(-?\d{1,2}\.\d{4,})["']?""",
    re.IGNORECASE,
)
```

要点：lat 组要求 `-?\d{1,2}\.\d{4,}`（**至少 4 位小数**，且整数部分最多 2 位）；lng 组 `-?\d{1,3}\.\d{4,}`；两键之间只允许 `,` 或 `;` 分隔（**不允许其它键插入**）；`_COORD_PAIR_RE2` 处理 lng 在前的情况，并**交换** `(m.group(2), m.group(1))`（`geo.py:83`）。

## §7 异常语义

### 7.1 `errors.py` 定义了什么

`errors.py` 全文只有 2 个类（10 行）：

| 类 | 行号 | docstring 原文 |
|---|---|---|
| `PlatformError(Exception)` | `errors.py:5-6` | `"""平台采集失败（可恢复，不拖垮其他平台）。"""` |
| `HumanVerificationError(PlatformError)` | `errors.py:9-10` | `"""遇到验证码/风控，需要真人处理（不自动破解）。"""` |

**全仓使用情况（grep 确证）**：`HumanVerificationError` **只被抛出 1 次**（`human.py:204`），**从未被 `except HumanVerificationError` 精确捕获**；`PlatformError` **从未被抛出、也从未被捕获**（只有 `errors.py:5,9` 两处定义 + `human.py:8,199,201,204` 的注释/import）。→ **`errors.py` 是纯命名约定，携程链路上没有任何按类型分派的异常处理。**

### 7.2 被吞成 `result["error"]`（对外可见为一行字符串）

| 场景 | 异常来源 | 落点 | 结果 |
|---|---|---|---|
| **整个采集流程的任何异常** | 任意 `Exception` | `ctrip.py:382-384`：`result["error"] = f"{type(exc).__name__}: {exc}"` + `logger.error` | 返回 `result`（`hotels` 保留已抽到的部分） |
| **验证码/风控** | `ensure_no_captcha`（`ctrip.py:325`）→ `HumanVerificationError`（`human.py:204`） | 被上面同一个宽 `except` 吞 | `error = "HumanVerificationError: 遇到验证码/风控，需要真人处理"`，**无专门分支、不重试、不告警、不改 headless** |
| **锚点彻底拿不到** | 非异常，显式赋值 | `ctrip.py:313-317` | 可操作中文指引（`hotels add` / `probe`），**早退 `return result`**（`ctrip.py:318`） |
| **单条报价无价** | 非异常，显式赋值 | `ctrip.py:375` | `"error": "" if h.get("price") is not None else "未识别到价格"` |

> 携程这条链路**唯一真正值钱的遗产是 §8.1#9 那条真接口**（`ctGetNearbyHotelList`：一条响应同时给出 `hotelId` / 酒店名 / 评分 / 点评数 / `position.lat,lng` / 距离文案 / SEO 详情 URL）；
